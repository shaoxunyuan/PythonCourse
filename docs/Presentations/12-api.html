客户端与服务器

客户端（你的代码）
  • 发起请求
  • 携带参数或正文
  • 解析返回结果

Python高级应用 · 网络、API 与大模型05

requests 调用示意

import requests

url = "https://httpbin.org/get"
resp = requests.get(url, timeout=10)
print(resp.status_code)
print(resp.text[:200])
  • timeout：避免无限等待
  • status_code：先看成功与否
  • text：原始文本；结构化数据再解析

POST 提交 JSON 示意

payload = {"question": "总结这段病程"}
resp = requests.post(
    "https://api.example.com/v1/chat",
    json=payload,
    timeout=30,
)
json=payload 会设置合适的 Content-Type，并把字典编码为 JSON。

状态码：先读「成没成功」

2xx 成功

如 200 OK
4xx 客户端问题

如 401 未授权、404 不存在
5xx 服务端问题

如 500 内部错误
拿到返回后，先判断状态码，再解析正文。

API 是什么？

API：应用程序接口——约定「怎么请求、返回什么」的说明书 + 服务入口。
  • URL：访问地址
  • 方法与参数：怎么传问题
  • 鉴权：如何证明你有权调用
  • 响应格式：成功/失败长什么样

学会读官方文档里的「请求示例」，比死记函数名更重要。

Python高级应用 · 网络、API 与大模型11

API Key：调用凭证

作用
证明「是谁在调用」，并关联配额与计费
形态
一串保密字符串，常放在请求头
风险
泄露后可能被盗用额度或越权访问
密钥等同于密码：能调接口的人，就能花你的额度。
Python高级应用 · 网络、API 与大模型12

安全原则：勿硬编码到公开仓库

不推荐
# 写死在源码里并推送公开仓库
API_KEY = "sk-xxxxxxxx"
更稳妥的方向
  • 用环境变量或本地私密配置
  • 配置文件加入忽略规则
  • 演示代码用占位符
原则表述：密钥不要写进会公开分享的代码里。

读取密钥的示意（概念）

import os

api_key = os.environ.get("MY_API_KEY")
if not api_key:
    raise RuntimeError("未配置 MY_API_KEY")
  • 程序启动时从环境读取，而不是写死在文件中
  • 分享代码时只保留变量名与说明
  • 若密钥曾误提交，应作废并更换

隐私与可靠性注意点

  • 尽量脱敏：姓名、住院号等按规范处理后再外发
  • 模型可能「幻觉」：看起来通顺但无依据
  • 网络会失败：超时、限流、5xx 都要有应对
  • 费用与配额：频繁调用前先看额度
能调用 ≠ 可直接当作正式病历结论。

出错时怎么排查？

401
鉴权失败 → 检查密钥是否配置、是否过期
429
请求过多 → 降频或稍后重试
超时
网络或服务慢 → 加大 timeout、检查连通性
字段
KeyError → 打印部分 JSON，对照文档路径
